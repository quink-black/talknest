# ESP32-S3 设备配置与音量控制设计

## 目标

设备当前的 Wi-Fi、服务器地址、模式、学习者和音频参数都通过 `firmware/config/talknest.json` 在编译期嵌入，任何调整都要重新构建和烧录。本设计让 TF 卡上的 `/sdcard/talknest.json` 覆盖编译期配置，使常用参数可以在不重新烧录固件的情况下修改：

- 编译期嵌入的配置作为出厂默认值。
- TF 卡上的 `/sdcard/talknest.json` 覆盖出厂默认值，适合一次性修改全部参数。

音量也通过这个文件调整，修改后重启设备生效。运行中的屏幕手势和 NVS 音量持久化留到后续阶段。

## 非目标

- 第一阶段不实现屏幕手势音量。
- 第一阶段不使用 NVS 保存音量。
- 第一阶段不实现通过 Web 页面配置设备。
- 不实现配置热重载；TF 卡配置在启动时读取，修改后需要重启设备。
- 不把 Wi-Fi 密码等敏感信息迁移到服务器。
- 不引入屏幕设置菜单或配网流程。

## 音频增益参数

`mic_gain_db` 和 `capture_gain` 作用在不同阶段：

- `mic_gain_db` 是 ES7210 的硬件 PGA 增益，作用在 ADC 之前。它能在量化前放大麦克风信号，改善信噪比；但过高会让大声说话削顶。
- `capture_gain` 是 ADC 之后的软件倍数，当前默认 8 倍（约 +18 dB）。它同时放大语音、环境噪声和量化噪声，不改善信噪比。

当前 `mic_gain_db = 36` 已经接近硬件上限，再叠加 `capture_gain = 8`，总增益很高。若语音识别稳定，可以保留；若出现削顶、破音或噪声明显，应先降低 `capture_gain`（例如降到 2–4），再考虑调整 `mic_gain_db`。校准时应以正常说话的峰值为准，保留约 6 dB 余量。

## 配置层级

启动顺序如下：

1. 解析编译期嵌入的 JSON，得到基础配置。
2. 尝试挂载 TF 卡。若挂载成功且 `/sdcard/talknest.json` 存在，解析该文件并覆盖基础配置中出现的字段；缺省字段保留基础值。
3. 卸载 TF 卡，释放文件系统和卡资源。
4. 用最终配置初始化 UI、音频和网络。

TF 卡不存在、挂载失败、文件缺失或 JSON 非法时，记录一条日志并继续使用上一层配置，不阻塞启动。

字段覆盖采用“出现即覆盖”：
- TF 文件可以只写需要修改的字段，例如仅写 `speaker_volume`。
- 未出现的字段保留嵌入式配置的值。

## TF 卡

BSP 已提供 `bsp_sdcard_mount()` 和 `bsp_sdcard_unmount()`，使用 SDMMC 1-bit，挂载点为 `/sdcard`。第一阶段只需要在启动时读取一个小 JSON 文件，读完立即卸载，避免 TF 卡长期供电。

要求：
- FAT32 文件系统。
- 文件名固定为 `talknest.json`，放在卡根目录。
- 文件大小限制为 8 KiB，超过则拒绝解析并记录错误。
- 配置内容与现有 `talknest.json` 字段一致，只允许覆盖已知字段。

TF 卡中的 Wi-Fi 密码是明文，这是可移动介质固有的风险；文档需要明确说明，设备丢失或卡片转手前应清除配置。

## 音量调整方式

第一阶段只通过 TF 卡配置文件调整音量：

- 在 `/sdcard/talknest.json` 中写入 `speaker_volume`，范围为 0–100。
- 重启设备后，新的音量在音频初始化时生效。
- 未写 `speaker_volume` 时沿用嵌入配置中的值。

屏幕手势、运行时音量和 NVS 持久化留给后续阶段；触摸仍然只用于播放中打断，不改变音量。

## 组件改动

- `app_config`：增加从文件解析配置的入口，支持在已有配置上覆盖字段；保留现有校验。
- `app_config`：负责 TF 卡挂载、文件读取、配置合并和卸载。
- `app_main`：在加载嵌入配置后应用 TF 卡覆盖，再用最终配置初始化客户端和音频。

## 多环境与 mDNS（后续阶段）

配置不再只有一份。`config/talknest*.json` 全部在编译期嵌入，按文件名排序，数量上限 8 份；开机扫描可见 SSID 并精确匹配各配置的 `wifi_ssid`，选中信号最强的一份，TF 卡的 `profile` 字段可以为隐藏网络强制指定环境。`server_url` 支持以 `.local` 结尾的 mDNS 主机名，服务器 IP 变化时无需重烧，但要求证书 SAN 覆盖该名称，且局域网 mDNS 把名字广播到设备可达的 IPv4 地址。

所有真实配置与 CA 文件都被 Git 忽略；排障查看通过 `scripts/show_device_config.sh` 脱敏，固件日志不输出凭据。字段说明与操作步骤见 `firmware/README.md`。

## 蓝牙配网（后续候选）

BLE GATT 配网需要限时进入配网模式、LE Secure Connections 配对与屏幕 passkey、NVS 持久化、配套配网工具，以及 BLE 与 Wi-Fi 在 2.4 GHz 的共存配置。它还涉及凭据存储安全与现场配对验证，因此不在本阶段实现。

## Web 配置（后续阶段）

Web 配置需要设备身份、服务器端设备注册表和一条从浏览器到设备的控制通道。当前 `/ws` 是每个客户端一个会话，浏览器和设备分别连接，服务端没有把两者关联起来的机制。直接增加配置接口会引入鉴权和多设备寻址问题，因此放在 TF 卡和本地音量之后。

## 验收

- 无 TF 卡时，设备使用嵌入配置正常启动。
- 插入 FAT32 TF 卡并写入 `/sdcard/talknest.json`，只覆盖 `speaker_volume`，重启后音量生效。
- TF 文件写坏或超过大小限制时，设备记录错误并继续使用嵌入配置。
- 修改 `capture_gain` 或 `mic_gain_db` 后无需重新烧录，重启即可生效。
- 轻触在播放中仍能打断，且不会被配置读取影响。

## 实施顺序

1. 配置解析重构，支持在已有配置上合并 TF 文件。
2. `app_config` 增加 TF 卡挂载、读取和卸载。
3. 真机验证无卡启动、部分字段覆盖、非法文件回退。
4. 再评估屏幕手势与 Web 配置。
