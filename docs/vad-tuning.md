# VAD 轮次切分与打断调参

轮次切分和打断的行为由 `server/config.yaml` 的 `vad` 段控制（每个参数都有
注释）。本文解释机制与调节代价，按“症状 -> 调哪个参数”组织。

## 轮次切分

`server/orchestrator/vad.py` 的 `StreamVAD` 把 24 kHz 流降采样到 16 kHz
逐帧喂 Silero：连续语音 `start_ms` 开口，尾部静音 `silence_ms` 收口，
起点前保留 `pre_roll_ms` 以免吃掉第一个字。`min_speech_ms` 过滤短促噪声
（咳嗽、椅子声），`max_speech_ms` 兜底防止卡住的麦克风无限录音。

症状 -> 调节：

- 一句话被切成两句（孩子说话停顿长）-> 调大 `silence_ms`。默认 700 是
  实测来的：500 时一段带自然停顿的合成语音 3 次里有 1 次被切开。
- 接话前等得太久 -> 调小 `silence_ms`，代价是停顿长的句子更容易被切分。

## 打断（barge-in）

助手播放期间仍检测语音，但要求持续 `barge_in_ms` 且概率超过
`barge_in_threshold` 才判定为孩子插话，播放开始后的 `playback_grace_ms`
内忽略——这些都是对抗“扬声器回声被麦克风拾取导致自我打断”的代价。
命中后服务端取消 LLM/TTS 并通知前端立即停播。

还没开口的轮次（ASR/LLM/TTS 进行中）没有回声要对抗，反而要护住“孩子
等得不耐烦说‘喂?’就把答案丢了”的情况：`pending_barge_in_ms` 窗口内的
插话不打断当前轮。

症状 -> 调节：

- 助手老是被自己打断（回声）-> 优先调大 `barge_in_ms`。
- 打断要喊很久才生效 -> 调小 `barge_in_ms` 或 `barge_in_threshold`。
  门槛抬高约损失 1 秒起判延迟，默认 0.6 是故意贴着线的。
- 孩子插话后助手仍把憋着的话说完 -> 调小 `pending_barge_in_ms`。

## 与音频设备的关系

麦克风和扬声器不属于同一个物理设备时（例如 HDMI 外放 + 蓝牙麦克风），
浏览器 AEC 的参考信号变弱，回声更容易触发假打断——此时也需要调大
`barge_in_ms`。设备选择的机制见 README 的“音频设备”一节。
